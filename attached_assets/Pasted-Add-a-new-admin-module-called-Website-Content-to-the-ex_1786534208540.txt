Add a new admin module called "Website Content" to the existing Al Mujaddidun Platform Admin Dashboard.

IMPORTANT:
- This is an ADMIN content management feature.
- Do NOT redesign the existing website.
- Do NOT change the existing visual identity, colors, typography, navbar, footer, or responsive behavior.
- Reuse the existing Admin Dashboard design system and components.
- Reuse the existing authentication and authorization system.
- Only authenticated users with the admin role can access this page.
- Do NOT use mock data for the final implementation.
- Connect the content to the existing database and backend/API.

ADMIN ROUTE:

/admin/content

Add "محتوى الموقع" / "Website Content" to the Admin Dashboard sidebar.

The page should allow the administrator to manage the content displayed on the public website.

- Arabic title

Create a section allowing the admin to control whether major homepage sections are visible.

Examples:

- About
- Programs
- Events
- News

- Partners
- Statistics

- Contact

Each section should have:

IMPORTANT:
The visibility/order settings must actually affect the public website.

DATABASE:

Before creating new tables, inspect the existing database schema.

If an existing settings/content structure can safely support this feature, extend it instead of creating duplicate structures.

If new database tables are required, create a clean normalized structure.

Suggested conceptual structure:

website_content
- id
- section_key
- content_type
- value_ar
- value_en
- image_url
- link_url
- is_active
- display_order
- created_at
- updated_at

For structured/repeatable content such as statistics, use a dedicated table rather than storing multiple records in one text field.

API:

Create/use proper authenticated admin API endpoints.

Examples:

GET    /api/admin/content
GET    /api/admin/content/:section
POST   /api/admin/content
PUT    /api/admin/content/:id
DELETE /api/admin/content/:id

For visibility/order:

GET    /api/admin/content-sections
PUT    /api/admin/content-sections/:id

Do NOT expose admin-only mutation endpoints publicly.

PUBLIC WEBSITE:

Update the public website to consume the content dynamically from the backend.

The public website must:
- Display Arabic content when Arabic is selected.
- Display English content when English is selected.
- Respect active/inactive status.
- Respect section display order.
- Gracefully handle missing optional content.
- Never expose raw translation keys.
- Never crash if a section has no content.

IMPORTANT:
Existing public content must not disappear during migration.

If current content is hardcoded, migrate the existing values into the database so the website looks exactly the same after switching to dynamic content.
